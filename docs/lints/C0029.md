## Parameters

| Name | Type | Default | Meaning |
|---|---|---|---|
| `pairs` | list of strings | `["-h=--help", "-V=--version", "-v=--verbose", "-q=--quiet", "-n=--dry-run", "-a=--all", "-o=--output", "-y=--yes"]` | short flags and the long flag each must stand for |

## Why

Short flags are muscle memory across tools: `-n` is a dry run, `-q` quiet, `-y` yes. A tool where `-n` means `--name` turns a habit into a mistake, and `-n` on a destructive command then runs it for real.

## Example

```text
Options:
  -n, --name <NAME>   <- -n stands for --dry-run
```

## How to fix

Give the flag another short form, or none. The parameter `pairs` lists each short flag and the long flag it stands for (`-n=--dry-run`); `-f` is not in the default list, because some tools use it for `--force` and others for `--format`.

## Configure

```toml
[lints.cli-standard-flags]
level = "deny"
pairs = ["-h=--help", "-V=--version", "-v=--verbose", "-q=--quiet", "-n=--dry-run", "-a=--all", "-o=--output", "-y=--yes"]
reason = "why this project wants it at this level"
```

Allow one finding in the code with `// spirit-level: allow(cli-standard-flags) <reason>` ([waivers](../waivers.md)); the code works there too, as in `[lints.C0029]`.
