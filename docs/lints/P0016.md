## Parameters

| Name | Type | Default | Meaning |
|---|---|---|---|
| `phrases` | list of strings | `["hmm", "wait,", "actually,", "i think", "i guess", "not sure", "let's see", "ok so", "okay so", "oops", "on second thought", "i wonder"]` | the phrases, matched as whole words, case-insensitive |
| `questions` | boolean | `true` | also report comments that end with a question mark |

## Why

A comment is read many times; it should hold the conclusion. "Hmm", "actually,", "I think" and open questions are the writer thinking aloud, often an agent's reasoning left in the code. They leave the reader to finish the thought.

The rule checks non-doc comments (`//`, `/* */`) for the `phrases`, and with `questions` on, for a comment that ends with `?` (URLs excepted).

```rust
// hmm, should this be u32?        <- two findings
// u16: the frame length field is two bytes.
```

## How to fix

Decide, and write the decision as a statement. An open question goes into FEATURES.md or an issue.

## Configure

```toml
[lints.thinking-comments]
level = "deny"
phrases = ["hmm", "wait,", "actually,", "i think", "i guess", "not sure", "let's see", "ok so", "okay so", "oops", "on second thought", "i wonder"]
questions = true
reason = "why this project wants it at this level"
```

Allow one finding in the code with `// spirit-level: allow(thinking-comments) <reason>` ([waivers](../waivers.md)); the code works there too, as in `[lints.P0016]`.
