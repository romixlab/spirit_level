# D0026 glossary-terms { #D0026 }

<a id="glossary-terms"></a>

**Rule:** A book that marks glossary terms marks each once in every section that uses it.

## Parameters

| Name | Type | Default | Meaning |
|---|---|---|---|
| `ignore` | list of strings | `[]` | terms that need no mark: everyday words the glossary also defines |

## Why

A book that turns on the glossary extension (`spl_book_ext.glossary`, see [References in prose](../refs.md)) shows a term's definition when the reader points at `[[term]]`. A reader arrives in any section, from search or a link, and needs that card where the section first uses the term. Marking every use would underline half of every page, so the rule is one mark per section, at the first use.

The lint reads the glossary the book's settings name and every page the book builds. In each section, the prose between two headings, a term written plainly but never marked is reported at its first use. Every form of a term counts (`forms` in the glossary), longer terms are matched first, and inline code is not read.

The words are matched without regard to sense, so the finding is an estimate: "blocks the thread" reads as the term "block". Terms that are also everyday words go into `ignore`:

```toml
[lints.glossary-terms]
level = "deny"
ignore = ["clock"]
```

## How to fix

Write the first use in the section as `[[pieces]]`, or `[[the end of the piece|tail]]` to show other words. Where the word does not mean the term, waive that line or rephrase it.

## Configure

```toml
[lints.glossary-terms]
level = "deny"
ignore = []
reason = "why this project wants it at this level"
```

Allow one finding in the code with `// spirit-level: allow(glossary-terms) <reason>` ([waivers](../waivers.md)); the code works there too, as in `[lints.D0026]`.
