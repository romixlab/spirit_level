# M0023 workspace-inheritance { #M0023 }

<a id="workspace-inheritance"></a>

**Rule:** Members inherit the shared package keys from [workspace.package].

## Parameters

| Name | Type | Default | Meaning |
|---|---|---|---|
| `keys` | list of strings | `["edition", "rust-version", "license", "repository"]` | the keys every member inherits |

## Why

Edition, rust-version, licence and repository are the same for every crate of a workspace. Declared once in `[workspace.package]` and inherited, they cannot drift apart, and a change is one line.

## Example

```toml
# root Cargo.toml
[workspace.package]
edition = "2024"
rust-version = "1.88"
license = "MIT OR Apache-2.0"

# crates/foo/Cargo.toml
[package]
name = "foo"
edition.workspace = true
rust-version.workspace = true
license.workspace = true
```

## How to fix

`spl check --fix` rewrites `key = "..."` into `key.workspace = true`, or adds the line after `name` when the key is missing. A key missing from `[workspace.package]` itself is added by hand. The keys checked are the parameter `keys`.

## Configure

```toml
[lints.workspace-inheritance]
level = "deny"
keys = ["edition", "rust-version", "license", "repository"]
reason = "why this project wants it at this level"
```

Allow one finding in the code with `// spirit-level: allow(workspace-inheritance) <reason>` ([waivers](../waivers.md)); the code works there too, as in `[lints.M0023]`.
